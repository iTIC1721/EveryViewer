# 멀티 탭 PDF 뷰어 — 기획서

| 항목 | 내용 |
|---|---|
| 가칭 | **TabPDF** (가칭) |
| 플랫폼 | **Android** (iOS는 MVP 이후 검토) |
| 문서 버전 | v0.3 (탭 인디케이터 제거) |
| 작성일 | 2026-10-24 |

---

## 1. 개요

### 1.1 배경
기존 모바일 PDF 뷰어는 대부분 **한 번에 하나의 파일**만 보여준다. 여러 문서를 번갈아 봐야 할 때(교재 + 해설지, 논문 여러 편, 악보 여러 장, 계약서 + 참고자료 등) 매번 파일 목록으로 돌아가 다시 열어야 하고, 앱을 끄면 보던 위치도 사라진다.

### 1.2 한 줄 정의
> **브라우저처럼 PDF를 탭으로 열어두고, 좌우로 넘기며 보고, 그룹으로 묶어 관리하는 가벼운 PDF 뷰어.**

### 1.3 핵심 가치
1. **동시에 여러 개** — PDF를 탭으로 무제한(실용 범위) 열어둔다.
2. **그대로 유지** — 앱을 꺼도 탭·그룹·읽던 페이지가 그대로 복원된다.
3. **빠른 전환** — 화면을 좌우로 밀어 탭을 넘긴다.
4. **정리** — 탭 그룹으로 용도별(과목/프로젝트 등) 분리 관리.
5. **가볍고 단순** — 보기 기능에 집중. 편집·주석·클라우드 등은 넣지 않는다.

### 1.4 하지 않는 것 (Non-goals)
- PDF 편집, 주석/필기, 서명, 폼 입력
- 클라우드 동기화, 계정/로그인
- 파일 관리자 기능(이동, 이름 변경, 삭제)
- 광고, 과도한 설정 화면

## 2. 타깃 사용자 및 사용 시나리오

| 사용자 | 시나리오 |
|---|---|
| 학생 | "토익" 그룹에 교재·해설·단어장 3개 탭, "전공" 그룹에 강의자료 5개 탭. 공부 중 교재 ↔ 해설을 좌우 스와이프로 오간다. |
| 연구자 | 논문 여러 편을 그룹으로 묶어 비교하며 읽는다. 다음 날 앱을 열면 읽던 페이지 그대로. |
| 연주자 | 공연 세트리스트 순서대로 악보 PDF를 탭으로 배치, 곡이 끝나면 스와이프로 다음 곡. |
| 직장인 | 회의 자료 묶음을 그룹 하나로 열어두고, 회의가 끝나면 그룹째 닫는다. |

## 3. 정보 구조 (IA)

```
앱
└─ 탭 그룹 (1개 이상, 순서 있음)
    └─ 탭 (0개 이상, 순서 있음)
        └─ PDF 문서 + 읽기 상태(페이지, 확대율, 스크롤 위치)
```

- 앱은 항상 **하나의 활성 그룹**과 그 안의 **하나의 활성 탭**을 가진다.
- 첫 실행 시 기본 그룹 **"기본"** 이 자동 생성된다.
- 그룹이 1개뿐이면 그룹 UI는 최소화되어 거의 보이지 않는다 → 그룹을 안 쓰는 사용자에게는 단순한 탭 뷰어로 보인다.

## 4. 화면 구성

화면은 사실상 **3개**뿐이다.

| # | 화면 | 역할 |
|---|---|---|
| A | 뷰어 (메인) | PDF를 보는 화면. 앱 시간의 95%를 여기서 보낸다. |
| B | 탭 개요 (탭 스위처) | 현재 그룹의 탭을 한눈에 보고 정렬/닫기/이동. |
| C | 그룹 시트 | 그룹 목록 전환·생성·이름변경·삭제. (바텀 시트) |

> 파일 선택은 OS 기본 파일 선택기(Android SAF / iOS Document Picker)를 그대로 사용 → 별도 화면을 만들지 않는다.

### 4.1 A. 뷰어 (메인 화면)

```
┌──────────────────────────────┐
│ [● 토익 ▾]  교재.pdf      [3] │ ← 상단 바 (얇게, 1줄)
├──────────────────────────────┤
│                              │
│                              │
│         PDF 페이지            │
│        (세로 연속 스크롤)      │
│                              │
│   ◀── 좌우 스와이프로 탭 전환 ──▶ │
│                              │
│                     12 / 240 │ ← 페이지 표시 (스크롤 중에만 잠깐)
└──────────────────────────────┘
```

**상단 바 구성 (좌→우)**
| 요소 | 동작 |
|---|---|
| 그룹 칩 `● 토익 ▾` (그룹 색상 점 + 이름) | 탭: 그룹 시트(C) 열기 |
| 현재 파일 이름 | 길면 말줄임. 길게 누르면 전체 이름 + 파일 정보 |
| 탭 개수 버튼 `[3]` | 탭: 탭 개요(B) 열기 (Chrome 모바일의 탭 버튼과 동일한 감각) |

- 상단 바 오른쪽 `⋮` 메뉴는 두지 않거나, 두더라도 항목 최소화: `PDF 열기`, `페이지 이동`, `설정`.
- **몰입 모드**: 화면을 한 번 탭하면 상단 바가 숨겨지고 PDF만 남는다. 다시 탭하면 표시.
- 탭이 하나도 없으면 가운데에 큰 **"＋ PDF 열기"** 버튼만 표시(빈 상태).

**스와이프 중 제목**
- 탭 위치(몇 번째 탭인지)는 표시하지 않는다. 고정된 제목 아래에서 따로 움직이는 인디케이터는 어색하고, 위치 정보 자체도 필요성이 낮다.
- 대신 스와이프하는 동안 파일 이름이 손가락을 따라 밀려나고, 다음 탭의 파일 이름이 흐리게 따라 들어온다 (인접 탭 미리보기).

### 4.2 B. 탭 개요 (탭 스위처)

```
┌──────────────────────────────┐
│ ←  토익 (3)              ＋   │
├──────────────────────────────┤
│ ┌──────┐ ┌──────┐ ┌──────┐   │
│ │ 썸네일 │ │ 썸네일 │ │ 썸네일 │   │
│ │      │ │      │ │      │   │
│ └──────┘ └──────┘ └──────┘   │
│  교재.pdf  해설.pdf  단어.pdf  │
│  p.12     p.3      p.40     │
└──────────────────────────────┘
```

- 2~3열 그리드, 각 카드: **현재 읽던 페이지 썸네일 + 파일명 + 페이지 번호**.
- 카드 탭 → 해당 탭으로 이동 후 뷰어로 복귀.
- 카드 **옆으로 밀기** 또는 `✕` → 탭 닫기 (실행 취소 스낵바 제공).
- 카드 **길게 눌러 드래그** → 순서 변경.
- 카드 길게 누르기 메뉴 → `다른 그룹으로 이동`, `닫기`, `파일 정보`.
- 우상단 `＋` → PDF 열기 (현재 그룹에 추가).

### 4.3 C. 그룹 시트 (바텀 시트)

```
┌──────────────────────────────┐
│  ───                         │
│  탭 그룹                      │
│  ● 기본          5개 탭        │
│  ● 토익          3개 탭   ✓    │
│  ● 전공 강의      7개 탭        │
│  ＋ 새 그룹                    │
└──────────────────────────────┘
```

- 항목 탭 → 해당 그룹으로 전환 (그 그룹의 마지막 활성 탭이 열림).
- 항목 길게 누르기 → `이름 변경`, `색상 변경`, `그룹 닫기(탭 모두 닫기)`, 드래그로 순서 변경.
- `＋ 새 그룹` → 이름 입력 다이얼로그 1개만. 색상은 자동 지정(이후 변경 가능).
- 마지막 그룹은 삭제 불가(최소 1개 유지). 비어 있는 그룹은 허용.

## 5. 핵심 기능 상세

### 5.1 PDF 열기
| 경로 | 동작 |
|---|---|
| 앱 내 `＋ PDF 열기` | OS 파일 선택기 → **다중 선택 지원** → 선택한 파일들이 현재 그룹 끝에 새 탭으로 추가, 첫 번째 파일로 이동 |
| 외부 앱에서 "공유/열기" (파일 앱, 메신저, 브라우저 다운로드 등) | 현재 활성 그룹에 새 탭으로 추가하고 바로 표시 |
| 이미 열린 파일을 또 열 경우 | 새 탭을 만들지 않고 **기존 탭으로 이동** (같은 그룹 내 중복 방지. 다른 그룹에 있으면 "토익 그룹에 이미 열려 있음 — 이동 / 여기에도 열기" 선택) |

### 5.2 탭 간 이동 — 좌우 스와이프 ★핵심
- 뷰어 화면에서 **좌우 스와이프 → 이전/다음 탭**으로 페이지 넘기듯 전환 (ViewPager 방식, 손가락 따라 화면이 움직이는 애니메이션).
- 그룹의 **첫/마지막 탭에서 더 밀면** 고무줄 효과로 막힌다. (다음 그룹으로 넘어가지 않음 — 그룹 경계는 명확하게 유지)
  - 설정에서 "그룹 끝에서 다음 그룹으로 넘어가기" 옵션 제공 가능 (기본 OFF).
- PDF 내부 스크롤은 **세로 방향 연속 스크롤**을 기본으로 하여 좌우 제스처와 충돌을 피한다.

**제스처 충돌 해결 규칙** (가장 중요한 UX 결정)

| 상태 | 좌우 스와이프 동작 |
|---|---|
| 확대하지 않은 상태(폭 맞춤) | **탭 전환** |
| 확대한 상태, 페이지 좌우 끝이 아님 | 확대된 페이지 **좌우 이동(팬)** |
| 확대한 상태, 페이지 좌/우 끝에 닿은 상태에서 한 번 더 밀기 | **탭 전환** (사진 갤러리 앱과 동일한 방식) |
| 두 손가락 | 항상 확대/축소 |

- 대각선 제스처는 시작 각도로 판정 (가로 성분이 세로의 약 2배 이상일 때만 가로 스와이프로 인정) → 세로 스크롤 중 실수로 탭이 넘어가는 것 방지.
- 멀리 떨어진 탭으로 바로 가려면 탭 개수 버튼 → 탭 개요(4.2)를 쓴다.

### 5.3 상태 유지 (세션 복원) ★핵심
앱을 완전히 종료(최근 앱에서 제거, 재부팅 포함)해도 다음이 **모두 그대로** 복원된다.

| 저장 항목 | 단위 |
|---|---|
| 그룹 목록, 이름, 색상, 순서 | 그룹 |
| 각 그룹의 마지막 활성 탭 | 그룹 |
| 탭 목록과 순서, 소속 그룹 | 탭 |
| 각 탭의 **페이지 번호, 확대율, 스크롤 위치** | 탭 |
| 마지막 활성 그룹 | 앱 |

- **저장 시점**: 변경 즉시(디바운스 0.5초) + 앱이 백그라운드로 갈 때 강제 저장 → 비정상 종료에도 손실 최소화.
- **복원 속도 목표**: 앱 실행 → 마지막 탭의 마지막 페이지 표시까지 **1초 이내**. 활성 탭만 즉시 렌더링, 나머지 탭은 필요할 때(인접 탭은 미리) 로드.

**파일 접근 권한 유지 (기술적 필수 사항)**
- Android: SAF `takePersistableUriPermission()`으로 **영구 URI 권한**을 받아 재시작 후에도 파일 접근 가능하게 한다.
- iOS: Security-scoped bookmark 저장.
- 외부 앱 공유로 받은 임시 파일(메신저 등)은 재시작 시 사라질 수 있으므로 **앱 내부 저장소로 복사**해서 연다 (복사본은 탭을 닫으면 삭제).

**파일이 없어졌을 때**
- 원본이 삭제/이동되어 열 수 없으면 탭은 유지한 채 "파일을 찾을 수 없습니다 — [다시 찾기] [탭 닫기]" 안내를 표시. 조용히 탭을 지우지 않는다.

### 5.4 탭 그룹 관리
| 기능 | 방법 |
|---|---|
| 그룹 만들기 | 그룹 시트 → `＋ 새 그룹` |
| 그룹 전환 | 상단 그룹 칩 탭 → 그룹 선택 |
| 탭을 다른 그룹으로 이동 | 탭 개요에서 카드 길게 누르기 → `다른 그룹으로 이동` (또는 "새 그룹으로 이동") |
| 그룹 이름/색상 변경 | 그룹 시트에서 길게 누르기 |
| 그룹 순서 변경 | 그룹 시트에서 드래그 |
| 그룹 닫기 | 그룹과 그 안의 탭 모두 닫기 (확인 다이얼로그 + 실행 취소) |

- 그룹 색상: 8색 정도의 고정 팔레트. 그룹 칩·탭 개요 헤더에 색으로 구분.

### 5.5 PDF 보기 (최소 기능)
| 기능 | 포함 여부 |
|---|---|
| 세로 연속 스크롤 | ✅ 기본 |
| 핀치 확대/축소, 더블탭 확대 | ✅ |
| 페이지 번호 표시 / 페이지 이동(번호 입력) | ✅ |
| 빠른 스크롤 바(오른쪽 끝 드래그) | ✅ |
| 다크 모드 (UI) | ✅ 시스템 설정 따름 |
| 화면 꺼짐 방지 | ✅ 설정 토글 |
| 텍스트 검색 | ⏳ 2차 |
| 목차(북마크) 보기 | ⏳ 2차 |
| 페이지 단위 가로 넘김 모드 | ❌ 탭 스와이프와 충돌하므로 제외 |
| 암호 PDF | ⏳ 2차 (열 때 비밀번호 입력, 저장하지 않음) |

### 5.6 설정 (최소화)
- 화면 꺼짐 방지 (ON/OFF)
- 그룹 끝에서 다음 그룹으로 넘어가기 (ON/OFF, 기본 OFF)
- 같은 파일 중복 열기 허용 (ON/OFF, 기본 OFF)
- 앱 정보 / 오픈소스 라이선스

## 6. 데이터 모델

```
TabGroup
  id: String (UUID)
  name: String
  color: Int            // 팔레트 인덱스
  order: Int
  activeTabId: String?  // 그룹 전환 시 복원할 탭

Tab
  id: String (UUID)
  groupId: String       // → TabGroup.id
  order: Int
  fileUri: String       // 영구 권한을 받은 URI 또는 내부 복사본 경로
  isInternalCopy: Bool  // true면 탭 닫을 때 파일 삭제
  displayName: String
  pageCount: Int
  lastPage: Int
  zoom: Float
  scrollOffset: Float   // 페이지 내 세로 위치 (0.0~1.0)
  lastOpenedAt: Long

AppState
  activeGroupId: String
```

- 저장소: 로컬 DB(Android Room / SQLite). 수십~수백 개 탭 규모에서도 충분히 가볍다.
- 썸네일: 탭 개요용 저해상도 이미지를 캐시 폴더에 저장 (지워져도 재생성 가능).

## 7. 기술 방향 (확정)

**Android 네이티브**로 개발한다. "가볍고 심플"이 최우선 목표이므로 앱 용량과 제스처 제어에 유리한 네이티브를 택했다. iOS는 MVP 반응을 본 뒤 검토한다.

| 항목 | 선택 |
|---|---|
| 언어/UI | Kotlin + Jetpack Compose (Material 3) |
| PDF 렌더링 | Android 기본 `PdfRenderer` (추가 용량 0, 가벼움) |
| 탭 스와이프 | Compose `HorizontalPager` |
| 저장 | Room |
| 파일 접근 | SAF (`ACTION_OPEN_DOCUMENT`) + `takePersistableUriPermission()` |
| 최소 지원 버전 | Android 8.0 (API 26) 이상 |

- `PdfRenderer`는 텍스트 검색·목차를 지원하지 않으므로, 2차 기능 도입 시 PDFium 기반 라이브러리로 교체를 검토한다. (렌더러 부분을 인터페이스로 분리해 두면 교체 비용이 작다.)

## 8. 비기능 요구사항

| 항목 | 목표 |
|---|---|
| 앱 용량 | 10MB 이하 (1안 기준) |
| 콜드 스타트 → 마지막 페이지 표시 | 1초 이내 |
| 탭 전환 애니메이션 | 60fps, 끊김 없음 |
| 메모리 | 활성 탭 + 좌우 인접 1개씩만 렌더링 유지, 나머지는 상태만 보관 |
| 대용량 PDF (500페이지+) | 보이는 페이지만 렌더링, 스크롤 끊김 없음 |
| 오프라인 | 완전 오프라인 동작, 네트워크 권한 불필요 |
| 개인정보 | 어떤 데이터도 외부 전송 없음 |

## 9. 개발 범위 및 일정 (안)

### MVP (1차)
- [ ] PDF 열기 (파일 선택기 다중 선택, 외부 앱 공유/열기)
- [ ] 세로 연속 스크롤 뷰어 + 핀치 줌 + 페이지 표시/이동
- [ ] 좌우 스와이프 탭 전환 (제스처 충돌 규칙 포함)
- [ ] 탭 개요 (썸네일 그리드, 닫기, 순서 변경)
- [ ] 탭 그룹 (생성, 전환, 이름/색상 변경, 탭 이동, 그룹 닫기)
- [ ] 세션 완전 복원 (영구 URI 권한, 페이지·확대율·스크롤 위치)
- [ ] 파일 누락 처리, 중복 열기 처리
- [ ] 다크 모드, 화면 꺼짐 방지

### 2차
- [ ] 텍스트 검색, 목차 보기
- [ ] 암호 PDF
- [ ] 최근 닫은 탭 다시 열기
- [ ] 태블릿 대응 (분할 화면으로 탭 2개 나란히 보기)

### 추후 검토
- [ ] iOS 버전

### 일정 (1인 개발 기준 예상)
| 단계 | 기간 |
|---|---|
| 1. 뷰어 + 스와이프 탭 전환 프로토타입 (제스처 검증) | 1주 |
| 2. 데이터 모델 + 세션 복원 | 1주 |
| 3. 탭 개요 + 그룹 관리 | 1~1.5주 |
| 4. 예외 처리, 성능 최적화, 테스트 | 1주 |
| **합계** | **약 4~5주** |

> 1단계에서 **스와이프 제스처 충돌**이 실제 손에 맞는지 가장 먼저 검증한다. 이 부분이 앱 사용감을 결정하는 핵심 리스크다.

## 10. 리스크 및 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| 확대 상태에서 좌우 스와이프가 탭 전환과 헷갈림 | 높음 | 5.2의 "끝에 닿은 뒤 한 번 더" 규칙, 프로토타입 단계에서 실사용 테스트 |
| 파일 접근 권한이 재부팅 후 사라짐 | 높음 | 영구 URI 권한 + 임시 파일은 내부 복사 |
| 탭이 매우 많을 때 메모리 부족 | 중간 | 인접 탭만 렌더링, 썸네일은 디스크 캐시 |
| 기본 `PdfRenderer`의 일부 PDF 호환성 문제 | 중간 | 렌더러를 인터페이스로 분리, 필요 시 PDFium으로 교체 |

## 11. 의사결정 기록

| # | 항목 | 결정 |
|---|---|---|
| 1 | 플랫폼 | **Android 단독**으로 MVP 개발. iOS는 추후 검토 |
| 2 | 그룹 끝에서 다음 그룹으로 넘어가기 | 기본값 **OFF** (설정에서 켤 수 있음) |
| 3 | 같은 파일을 여러 그룹에 동시에 열기 | **확인 후 허용** ("이동 / 여기에도 열기" 선택). 같은 그룹 안에서는 중복 열지 않고 기존 탭으로 이동 |
| 4 | 앱 이름 | 가칭 **TabPDF** 유지 (출시 전 확정) |
| 5 | 탭 위치 인디케이터 | **표시하지 않음.** 프로토타입에서 제목 아래 움직이는 선이 어색했음. 스와이프 중 제목이 따라 움직이는 것으로 대체 |
