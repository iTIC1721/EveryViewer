## 1. 개요

### 1.1 배경
기존 모바일 문서 뷰어는 대부분 **한 번에 하나의 파일**만 보여주고, 형식마다 다른 앱으로 열어야 한다. 여러 문서를 번갈아 봐야 할 때(교재 + 해설지, 논문 여러 편, 악보 여러 장, 계약서 + 참고자료, 회의 자료 PDF + 발표 pptx + 메모 txt 등) 매번 파일 목록으로 돌아가 다시 열어야 하고, 앱을 끄면 보던 위치도 사라진다.

### 1.2 한 줄 정의
> **PDF·문서·이미지·텍스트 등 어떤 파일이든 브라우저처럼 탭으로 열어두고, 좌우로 넘기며 보고, 그룹으로 묶어 관리하고, 그 위에 필기하는 뷰어.**

### 1.3 핵심 가치
1. **동시에 여러 개** — 파일을 탭으로 무제한(실용 범위) 열어둔다.
2. **무엇이든 같은 방식으로** — 형식과 상관없이 모든 파일을 세로로 이어지는 페이지로 보여준다 (5.7).
3. **그대로 유지** — 앱을 꺼도 탭·그룹·읽던 위치·필기가 그대로 복원된다.
4. **빠른 전환** — 화면을 좌우로 밀어 탭을 넘긴다.
5. **정리** — 탭 그룹으로 용도별(과목/프로젝트 등) 분리 관리.
6. **보면서 적기** — 열린 탭 위에 펜·형광펜으로 필기한다. 원본 파일은 건드리지 않는다 (5.8).
7. **단순** — 보기와 필기에 집중한다. 화면과 설정을 늘리지 않는다. 정보는 글자보다 그림·아이콘·색으로 전한다 (글자는 화면 낭독기용 설명과 설정·오류 안내처럼 꼭 필요한 곳에만).

### 1.4 하지 않는 것 (Non-goals)
- 원본 파일 수정·편집, 필기를 파일에 저장하기, 서명, 폼 입력
- 인쇄 미리보기 수준의 정확한 재현 (원본과 크게 틀어지지 않는 수준이 목표, 5.7)
- 클라우드 동기화, 계정/로그인
- 파일 관리자 기능(이동, 이름 변경, 삭제)
- 광고, 과도한 설정 화면

|---|---|
| 학생 | "토익" 그룹에 교재 PDF·해설·단어장 txt 3개 탭, "전공" 그룹에 강의자료 pptx·PDF 5개 탭. 교재 ↔ 해설을 좌우로 오가며 교재 탭 위에 S펜으로 밑줄과 메모를 남긴다. |

## 3. 정보 구조 (IA)

Chrome 모바일 앱의 탭 그룹 구조를 따른다.

```
앱
└─ 최상위 목록 (순서 있음) — 아래 두 가지가 섞여 있다
    ├─ 그룹 없는 탭
    └─ 탭 그룹 (이름, 색상)
        └─ 탭 (1개 이상, 순서 있음)
탭 = 파일 + 읽기 상태(페이지, 확대율, 스크롤 위치) + 필기
```

- 탭은 그룹에 **속하지 않아도 된다** (기본 상태). 그룹은 필요할 때만 만든다 → 그룹을 안 쓰는 사용자에게는 단순한 탭 뷰어로 보인다.
- 빈 그룹은 없다. 그룹의 마지막 탭이 닫히거나 빠지면 그룹도 사라진다.
- 앱은 **현재 탭** 하나를 기억한다. 현재 탭이 속한 곳(그룹 또는 그룹 없음)이 뷰어의 스와이프 범위가 된다 (5.2).
- 필기는 파일이 아니라 **탭**에 속한다. 같은 파일을 두 탭으로 열면 필기도 따로다 (5.8).

## 4. 화면 구성

화면은 사실상 **3개**뿐이다.

| # | 화면 | 역할 |
|---|---|---|
| A | 뷰어 (메인) | 파일을 보고 필기하는 화면. 앱 시간의 95%를 여기서 보낸다. |
| B | 탭 전환 화면 | 모든 탭과 그룹을 한눈에 보고 열기/닫기/정렬/그룹 만들기. |
| C | 그룹 패널 | 그룹 하나의 탭 관리, 이름·색상 변경. (탭 전환 화면 위에 뜨는 패널) |

> 파일 선택은 OS 기본 파일 선택기(Android SAF / iOS Document Picker)를 그대로 사용 → 별도 화면을 만들지 않는다.

### 4.1 A. 뷰어 (메인 화면)

```
┌──────────────────────────────┐
│ 교재.pdf          ✎  ＋ [5] ⋮│ ← 상단 바 (얇게, 1줄)
├──────────────────────────────┤
│                              │
│                              │
│      페이지 (세로 연속 스크롤)  │
│                              │
│   ◀── 좌우 스와이프로 탭 전환 ──▶ │
│                              │
│                     12 / 240 │ ← 페이지 표시 (스크롤 중에만 잠깐)
└──────────────────────────────┘
```

**상단 바 구성 (좌→우)**
| 요소 | 동작 |
|---|---|
| 현재 파일 이름 | 길면 말줄임 |
| `✎` 필기 | 필기 모드 켜기/끄기 (5.8). 켜면 필기 도구 막대가 나타난다 |
| `＋` | 파일 열기. 현재 탭이 그룹 안이면 그 그룹에, 아니면 그룹 없는 탭으로 연다 |
| 탭 개수 버튼 `[5]` | 전체 탭 수. 탭: 탭 전환 화면(B) 열기 (Chrome 모바일의 탭 버튼과 동일한 감각). 그룹 안의 탭을 볼 때는 그 그룹 색으로 칠해진다 (11장 18번) |
| `⋮` | `찾기`(5.5), `목차`(5.5), `페이지 이동`, `PDF로 내보내기`(5.9), `설정`(5.6) |

- **몰입 모드**: 화면을 한 번 탭하면 상단 바가 숨겨지고 문서만 남는다. 다시 탭하면 표시. 필기 모드에서는 몰입 전환을 하지 않는다 (도구가 사라지지 않게. 줄인 화면의 빈 곳을 눌러도 그대로).
- 탭이 하나도 없으면 가운데에 큰 **"＋ 파일 열기"** 버튼만 표시(빈 상태).

**스와이프 중 제목**
- 탭 위치(몇 번째 탭인지)는 표시하지 않는다. 고정된 제목 아래에서 따로 움직이는 인디케이터는 어색하고, 위치 정보 자체도 필요성이 낮다.
- 대신 스와이프하는 동안 파일 이름이 손가락을 따라 밀려나고, 다음 탭의 파일 이름이 흐리게 따라 들어온다 (인접 탭 미리보기).

**필기 도구 막대** (필기 모드일 때만, 상단 바 바로 아래 한 줄)
```
│  ✒  ▮  ▯                      ☝  ↶  ↷ │   ← 서 있는 펜·형광펜·지우개 그림 (촉 = 현재 색, 고른 도구는 위로)
```
- `☝`(손가락으로 그리기)는 펜을 쓰는 기기에서만 보인다 (5.8.3).
- 도구를 고르고, 고른 도구를 한 번 더 누르면 그 도구의 패널이 열린다: 프리셋 줄(5.8.2), 한 줄의 둥근 색 견본(기본 색 + 최근에 직접 고른 색이 남는 칸만큼 + 무지개 고리(직접 고르기)), 현재 색·굵기로 그린 미리보기 선(실제 화면 크기), 굵기 슬라이더와 그 값(숫자). 패널 안에 제목 글자는 두지 않는다.
- 직접 고르기: 채도·밝기 사각형과 색상 띠, 이전 색과 새 색을 나란히 보여주고 취소(✕)·확인(✓) 아이콘.
- 필기 모드에서는 상단 바와 도구 막대가 숨지 않는다 (몰입 모드 참고).

### 4.2 B. 탭 전환 화면

```
┌──────────────────────────────┐
│ ←  탭 5개                 ＋  │
├──────────────────────────────┤
│ ┌──────────┐ ┌──────────┐    │
│ │  썸네일 ✕│ │ ┌──┬──┐ ✕│    │
│ │          │ │ ├──┼──┤  │    │ ← 그룹 카드 (페이지 4장 콜라주)
│ └──────────┘ └──────────┘    │
│  교재.pdf      ● 토익         │
│  p.12          탭 3개         │
└──────────────────────────────┘
```

- 2~3열 격자에 **그룹 없는 탭 카드**와 **그룹 카드**가 최상위 순서대로 섞여 있다.
- 탭 카드: 현재 읽던 페이지 썸네일(필기 포함) + 파일명 + 페이지 번호. 현재 탭은 테두리로 강조.
- 그룹 카드: 그룹 탭 최대 4개의 썸네일 콜라주(그룹 색상 배경) + 이름 + 탭 수. 현재 탭이 들어 있으면 테두리로 강조.

| 조작 | 탭 카드 | 그룹 카드 |
|---|---|---|
| 탭 | 그 탭 열기 | 그룹 패널(C) 열기 |
| `✕` 또는 옆으로 밀기 | 탭 닫기 | 그룹 닫기 (탭 모두) |
| 길게 눌러 끌기 | 순서 변경 / 다른 카드 위에 놓아 그룹에 넣기 (아래) | 순서 변경 |
| 길게 눌렀다 떼기 (메뉴) | `그룹에 추가`, `파일 정보`, `닫기` | `이름 변경`, `색상 변경`, `그룹 해제`, `그룹 닫기` |

**끌어서 그룹 만들기** (Chrome·홈 화면 폴더와 같은 방식)
- 탭 카드를 **다른 탭 카드 한가운데**에 놓으면 → 두 탭으로 새 그룹 (이름 없음, 색상 자동).
- 탭 카드를 **그룹 카드 한가운데**에 놓으면 → 그 그룹 끝에 추가.
- 카드 **가장자리에 잠시(0.3초) 머물면** → 그 자리로 순서 변경. 가운데로 가는 길에 가장자리를 지나쳐도 순서가 바뀌지 않게 하기 위한 판정.
- 가운데에 올라가 있는 동안 대상 카드가 살짝 작아지고 색이 덮여 "놓으면 합쳐진다"를 보여준다.
- 우상단 `＋` → 파일 열기 (그룹 없는 탭으로).

### 4.3 C. 그룹 패널

탭 전환 화면에서 그룹 카드를 누르면 화면 위에 뜬다 (Chrome의 탭 그룹 대화상자).

```
┌──────────────────────────────┐
│ ●  토익            ＋  ⋮  ✕  │
├──────────────────────────────┤
│ ┌──────────┐ ┌──────────┐    │
│ │  썸네일 ✕│ │  썸네일 ✕│    │
│ └──────────┘ └──────────┘    │
│  교재.pdf      해설.pdf       │
└──────────────────────────────┘
```

- 색 점 탭 → 색상 변경, 이름 탭 → 이름 변경 (비워 두면 "탭 n개"로 표시).
- `＋` → 이 그룹에 파일 열기. `⋮` → `그룹 해제`(탭은 그룹 없는 탭으로 그 자리에 남음), `그룹 닫기`.
- 탭 카드: 탭 → 열기, `✕`/옆으로 밀기 → 닫기, 길게 눌러 끌기 → 그룹 안 순서 변경, 메뉴 → `그룹에서 빼기`(그룹 바로 뒤에 그룹 없는 탭으로), `파일 정보`, `닫기`.
- 그룹 밖으로 끌어내기 (Android 런처의 앱 폴더와 같은 방식): 탭을 끄는 동안 머리 줄이 위로 나가는 화살표(그룹 색 테두리)로 바뀐다. 그 위로 끌어 올리면 패널이 사라지고, 탭은 손가락에 붙은 채 그룹 없는 탭이 되어 탭 전환 화면에서 계속 끌린다. 놓는 곳에 따라 탭 전환 화면의 끌기와 같다: 빈 자리 → 그 자리에 그룹 없는 탭, 다른 탭 가운데 → 둘로 새 그룹, 그룹 카드 → 그 그룹으로 옮김 (원래 그룹 카드면 되돌아감).

### 4.4 시각 디자인

문서가 주인공이다. 바·카드·패널은 **종이**색으로 조용히 두고, 뷰어와 탭 전환 화면의 뒤는 한 단계 어두운 **책상**색으로 칠해 페이지가 책상 위에 놓인 종이처럼 보이게 한다 (코드: `ui/theme/`).

- 색: 앱 아이콘의 보라에서 뽑은 고정 팔레트. 강조색(잉크 보라)은 상태를 알릴 때만 쓴다 (필기 켜짐, 현재 탭, 선택, 끄는 중인 스크롤 손잡이). 글자는 배경과 4.5:1 이상, 아이콘·윤곽선은 3:1 이상.
  - 그룹 8색, 펜·형광펜 색, 검색 강조색, 문서 내용 색은 테마와 상관없이 그대로 둔다.
  - 밝은 테마에서는 페이지 둘레에 1픽셀 선과 아래쪽 옅은 그림자를 그린다. 어두운 테마에서는 흰 페이지가 그대로 떠 보여 그리지 않는다.
- 글꼴: 앱 화면 글자만 **Pretendard Std** (Regular·Medium·SemiBold). 문서는 각자의 글꼴로 조판한다. Std판에 없는 한글 글자는 시스템 글꼴로 대신 그린다.
- 모양: 모서리 반경은 크기에 따라 5단계 — 손잡이 4dp, 작은 조작 요소 8dp, 카드 14dp, 서랍 20dp, 패널·대화상자 28dp.
- 움직임: 사용자가 한 동작에 답할 때만 움직인다 (열기·닫기·집어 들기). 전체 화면(탭 전환·설정·묶음 편집·앱 정보)은 아래에서 살짝 올라오며 나타나고, 그룹 패널은 커지며 나타난다. 끄는 카드는 커지고, 합쳐질 카드는 작아진다. 시스템의 "애니메이션 삭제"를 따른다.
- 시작 화면: 창 배경을 책상색으로 해 앱이 뜨는 동안 색이 바뀌지 않게 한다. Android 12+에서는 앱 설정의 밝게/어둡게를 시스템에 알려 시작 창도 그 색으로 뜬다.

## 5. 핵심 기능 상세

### 5.1 파일 열기
| 경로 | 동작 |
|---|---|
| 앱 내 `＋ 파일 열기` | OS 파일 선택기(모든 파일) → **다중 선택 지원** → 선택한 파일들을 **연 위치**(뷰어: 현재 탭이 있는 곳 / 탭 전환 화면: 그룹 없는 탭 / 그룹 패널: 그 그룹)의 끝에 새 탭으로 추가, 첫 번째 파일로 이동 |
| 여러 파일을 함께 열 때 (파일 선택기에서 여러 개, 다른 앱에서 여러 개 공유) | "따로 열기 / 하나로 묶어 열기"를 묻는다. 묶으면 **파일 묶음** 탭 하나(아래). 그룹 밖에서 열면 "따로 열기"가 "그룹으로 열기"가 되어 이름 없는 **새 그룹**(맨 뒤)으로 연다 (설정 "여러 파일은 새 그룹으로 열기", 기본 켜짐) |
| 외부 앱에서 "공유/열기" (파일 앱, 메신저, 브라우저 다운로드 등) | 그룹 없는 새 탭으로 추가하고 바로 표시 |
| 파일 없이 글만 공유 (링크, 선택한 문장) | 그 글을 텍스트 파일로 저장해 새 탭으로 연다. 이름은 공유 제목, 없으면 "공유한 텍스트". 복사본처럼 탭을 닫으면 삭제 |
| 이미 열린 파일을 또 열 경우 | 묻지 않고 **새 탭으로 연다** (브라우저가 같은 페이지를 두 탭으로 여는 것처럼). 탭마다 읽던 위치와 필기가 따로다 (11장 3번) |
| 지원하지 않는 형식 | 탭은 만들되 "이 형식은 열 수 없습니다" 안내와 `탭 닫기`를 표시 (5.7) |

**파일 묶음** (11장 23번)
- 여러 파일(형식 무관: PDF·문서·이미지·텍스트를 섞어도 됨)의 쪽을 고른 순서대로 이어 한 문서처럼 본다. 이름은 "첫 파일 이름 외 n개", 탭 전환 화면·그룹·스와이프·읽던 위치·필기는 보통 탭과 같다.
- 검색·선택·링크는 각 쪽이 속한 파일의 것을 쓴다 (PDF 문서 안 링크는 묶음 안의 그 쪽으로).
- 열 수 없는 파일(지워짐 등)은 그 자리에 "열 수 없는 파일 + 이름" 빈 쪽 하나. 나머지는 그대로 열린다.
- `⋮` → `묶음 편집` (모든 탭; 파일 하나짜리 탭은 그 파일 카드 하나로 시작하고, 파일을 더하면 그 탭이 파일 묶음이 된다 — 처음 파일이 맨 앞이라 필기·읽던 위치가 그대로다. 11장 38번): 탭 전환 화면처럼 파일마다 카드(첫 쪽, 순번, 이름). 길게 눌러 끌기 → 순서 변경, `✕`/옆으로 밀기 → 빼기(마지막 하나는 뺄 수 없음), `＋` → 파일 추가, 이름 누르기 → 이름 변경. 뒤로 나갈 때 한 번에 적용한다.
- 편집 단위는 **파일**이다 (PDF 안의 쪽 하나를 빼거나 옮기지는 않는다). 순서가 바뀌면 필기와 읽던 위치가 그 파일의 쪽을 따라가고, 뺀 파일의 필기는 함께 지운다.
- 저장: 앱 안에 파일 목록(`files/bundles/*.json`)을 두고 탭이 그것을 가리킨다. 각 파일의 접근 권한·복사본은 보통 탭처럼 받고, 어느 탭·묶음도 쓰지 않게 될 때 놓는다.

- 외부 앱 "열기/공유" 대상: 5.7의 형식별 MIME 타입. 파일 관리자·메신저가 hwpx·md 등을 `application/octet-stream`으로 넘기는 경우가 많으므로 이 타입도 받고, 확장자와 내용으로 형식을 판별한다.

### 5.2 탭 간 이동 — 좌우 스와이프 ★핵심
- 뷰어 화면에서 **좌우 스와이프 → 이전/다음 탭**으로 페이지 넘기듯 전환 (ViewPager 방식, 손가락 따라 화면이 움직이는 애니메이션).
- **스와이프 범위**: 현재 탭이 그룹 안이면 **그 그룹의 탭들 사이에서만**, 그룹 없는 탭이면 **그룹 없는 탭들 사이에서만** 넘어간다.
- 범위의 **첫/마지막 탭에서 더 밀면** 고무줄 효과로 막힌다. (그룹 경계를 넘지 않음)
  - 설정 "그룹 끝에서 다음 그룹으로 넘어가기"(기본 OFF)를 켜면 범위가 **모든 탭**이 된다: 탭 전환 화면의 순서대로, 그룹은 그 자리에서 펼쳐서 이어 넘긴다. 그룹의 마지막 탭 다음은 화면상 다음 항목(그룹 없는 탭, 또는 다음 그룹의 첫 탭). 상단 바의 그룹 색·＋(파일 열기)·탭 전환 화면은 지금 보는 탭의 그룹을 따른다.
- 문서 내부 스크롤은 **세로 방향 연속 스크롤**을 기본으로 하여 좌우 제스처와 충돌을 피한다. 형식과 상관없이 같다.

**제스처 충돌 해결 규칙** (가장 중요한 UX 결정)

| 상태 | 좌우 스와이프 동작 |
|---|---|
| 확대하지 않은 상태(폭 맞춤), 또는 폭보다 줄인 상태 | **탭 전환** |
| 확대한 상태, 페이지 좌우 끝이 아님 | 확대된 페이지 **좌우 이동(팬)** |
| 확대한 상태, 페이지 좌/우 끝에 닿은 상태에서 한 번 더 밀기 | **탭 전환** (사진 갤러리 앱과 동일한 방식) |
| 두 손가락 | 항상 확대/축소 |

- 대각선 제스처는 시작 각도로 판정 (가로 성분이 세로의 약 2배 이상일 때만 가로 스와이프로 인정) → 세로 스크롤 중 실수로 탭이 넘어가는 것 방지.
- 멀리 떨어진 탭이나 다른 그룹으로 가려면 탭 개수 버튼 → 탭 전환 화면(4.2)을 쓴다.
- 필기 모드에서 손가락으로 그릴 때는 위 규칙이 두 손가락으로 옮겨간다 (5.8.3).
- 확대 범위: 화면 폭의 **50%~500%** (11장 33번). 폭보다 줄이면 쪽은 화면 가운데에 놓이고 양옆은 빈 공간이 된다. 두 번 탭: 100%가 아니면 100%로, 100%면 확대. 세로로 아주 긴 쪽이 있는 문서는 화면에 놓인 쪽 높이가 약 20만 px을 넘지 않도록 최대 배율이 낮아진다 (11장 37번).

### 5.3 상태 유지 (세션 복원) ★핵심
앱을 완전히 종료(최근 앱에서 제거, 재부팅 포함)해도 다음이 **모두 그대로** 복원된다.

| 저장 항목 | 단위 |
|---|---|
| 최상위 순서 (그룹 없는 탭과 그룹이 섞인 순서) | 앱 |
| 그룹 이름, 색상, 그룹 안 탭 순서 | 그룹 |
| 각 탭의 **페이지 번호, 확대율, 스크롤 위치** | 탭 |
| 각 탭의 **필기** | 탭 |
| 현재 탭 | 앱 |

- **저장 시점**: 변경 즉시(디바운스 0.5초, 필기는 획을 마칠 때마다) + 앱이 백그라운드로 갈 때 강제 저장 → 비정상 종료에도 손실 최소화.
- **복원 속도 목표**: 앱 실행 → 마지막 탭의 마지막 페이지 표시까지 **1초 이내** (PDF·이미지·텍스트 기준. 오피스 문서는 해석 시간 때문에 8장 목표 따로). 활성 탭만 즉시 렌더링, 나머지 탭은 필요할 때(인접 탭은 미리) 로드.

**파일 접근 권한 유지 (기술적 필수 사항)**
- Android: SAF `takePersistableUriPermission()`으로 **영구 URI 권한**을 받아 재시작 후에도 파일 접근 가능하게 한다.
- iOS: Security-scoped bookmark 저장.
- 외부 앱 공유로 받은 임시 파일(메신저 등)은 재시작 시 사라질 수 있으므로 **앱 내부 저장소로 복사**해서 연다 (복사본은 탭을 닫으면 삭제).

**파일이 없어졌을 때**
- 원본이 삭제/이동되어 열 수 없으면 탭은 유지한 채 "파일을 찾을 수 없습니다 — [다시 찾기] [탭 닫기]" 안내를 표시. 조용히 탭을 지우지 않는다.
- 다시 찾은 파일 위에도 기존 필기를 그대로 둔다. 내용이 바뀐 파일이면 위치가 어긋날 수 있다 (알리지 않음).

### 5.4 탭 그룹 관리
| 기능 | 방법 |
|---|---|
| 그룹 만들기 | 탭 전환 화면에서 탭을 다른 탭 위로 끌어다 놓기 / 탭 메뉴 → `그룹에 추가` → `새 그룹` |
| 그룹에 탭 넣기 | 탭을 그룹 카드 위로 끌어다 놓기 / 탭 메뉴 → `그룹에 추가` |
| 그룹에서 탭 빼기 | 그룹 패널에서 탭 메뉴 → `그룹에서 빼기` |
| 다른 그룹 보기 | 탭 전환 화면에서 그룹 카드 탭 → 그룹 패널에서 탭 선택 |
| 그룹 이름/색상 변경 | 그룹 패널 머리글 / 그룹 카드 메뉴 |
| 순서 변경 | 탭 전환 화면(최상위), 그룹 패널(그룹 안)에서 길게 눌러 끌기 |
| 그룹 해제 | 그룹 카드 메뉴 / 그룹 패널 `⋮` → 탭은 그룹 없는 탭으로 그 자리에 남음 |
| 그룹 닫기 | 그룹 카드 `✕`·밀기 / 메뉴 → 그룹과 탭 모두 닫기 (실행 취소 가능) |

- 그룹 색상: 8색 고정 팔레트, 새 그룹은 아직 안 쓴 색부터 자동 지정.
- 닫기는 확인 대화상자 대신 **실행 취소 스낵바(약 10초)** 로 되돌릴 수 있게 한다. 되돌리면 **필기도 함께** 돌아온다.
- 탭을 그룹 사이로 옮겨도 필기는 탭을 따라간다.

### 5.5 보기 (최소 기능)
| 기능 | 포함 여부 |
|---|---|
| 세로 연속 스크롤 | ✅ 기본 (모든 형식) |
| 핀치 확대/축소(50%~500%), 더블탭 확대 | ✅ |
| 페이지 번호 표시 / 페이지 이동(번호 입력) | ✅ |
| 빠른 스크롤 바(오른쪽 끝 드래그. 위치는 실제 스크롤 거리 비율이라 쪽 크기가 달라도 고르게 움직이고, 막대를 잡으면 잡은 자리를 유지한다) | ✅ |
| 다크 모드 (UI) | ✅ 시스템 설정 따름 / 밝게 / 어둡게 (설정, 5.6). 문서 내용 색은 원본 그대로 |
| 화면 꺼짐 방지 | ✅ 설정 토글 |
| 텍스트 검색 | ✅ 아래 "텍스트 검색" |
| 목차(북마크) 보기 | ✅ 아래 "목차" |
| 페이지 단위 가로 넘김 모드 | ❌ 탭 스와이프와 충돌하므로 제외 (pptx도 세로로) |
| 암호 PDF | ✅ 아래 "암호 PDF" |
| 텍스트 선택·복사 | ✅ 아래 "텍스트 선택·복사" |

**텍스트 검색**
- `⋮` → `찾기`: 상단 바가 찾기 막대로 바뀐다 (브라우저의 페이지 내 찾기와 같은 모양): 입력칸(비었을 때 돋보기 아이콘), `현재/전체` 개수, `∧` 이전, `∨` 다음, `✕` 닫기. 키보드의 검색 키 = 다음. 뒤로 가기로도 닫힌다.
- 입력하는 대로 찾는다 (0.25초 쉬었다가). 대소문자 무시. 한글 단어 줄바꿈용으로 넣은 보이지 않는 문자는 건너뛴다.
- 찾은 곳은 모두 노란색, 지금 결과는 주황색(테두리 포함)으로 칠한다. 필기는 그 위에 그대로 보인다. 지금 결과가 화면 밖이면 화면 위쪽 1/3 지점으로 옮기고, 확대 중이면 가로로도 옮긴다.
- 찾기는 지금 탭에서 한다. 찾기 막대를 연 채 탭을 넘기면 같은 말로 새 탭을 찾는다.
- 형식별: txt·md·docx·hwpx·pptx는 조판된 글에서 찾는다 (docx·hwpx 머리말·꼬리말은 매 쪽 반복이라 제외). PDF는 Android의 PDF 글자 기능으로 찾는다 — Android 15 이상, 또는 시스템 업데이트로 그 기능을 받은 Android 12~14 (11장 16번). 이미지나 그보다 오래된 기기의 PDF처럼 글자를 알 수 없으면 막지 않고 결과가 0개로 나온다.
- 결과는 1000개까지 모은다 (넘으면 `1000+`).

**텍스트 선택·복사** (Android 기본 텍스트 선택과 같은 동작)
- 글자를 **길게 누르면** 그 단어가 선택된다 (진동). 손가락을 떼지 않고 끌면 선택이 늘어난다.
- 선택 양 끝에 물방울 모양 손잡이가 나오고, 끌어서 범위를 바꾼다. 쪽을 넘어 선택할 수 있다 (한 번에 200쪽까지).
- 선택 위(자리가 없으면 아래)에 `복사` `공유` 막대가 뜬다 (Android 텍스트 막대의 관례대로 글자 버튼). 복사하면 Android 13 이상은 시스템이 알려 주고, 그 아래는 "복사했습니다" 안내를 잠깐 띄운다.
- 빈 곳을 누르거나 뒤로 가기로 선택을 푼다. 필기 모드를 켜면 선택이 풀리고, 필기 모드에서는 길게 눌러도 선택하지 않는다 (펜·손가락 필기와 겹치지 않게).
- 읽는 순서: 문단·표 칸 순서, 슬라이드는 도형 순서, docx·hwpx는 머리말 → 본문 → 꼬리말. 쪽이 바뀌는 곳은 줄바꿈으로 잇는다.
- PDF는 검색과 같은 Android의 PDF 글자 기능을 쓴다 (11장 16번). 이미지처럼 글자가 없는 곳은 길게 눌러도 아무 일도 없다.

**목차** (11장 31번)
- `⋮` → `목차`: 왼쪽에서 서랍이 나온다 (전자책 앱의 관례). 폭은 화면의 85%, 최대 360dp. 바깥을 누르거나 뒤로 가기로 닫는다.
- 항목마다 제목과 쪽 번호. 하위 항목은 `›`로 접혀 있고 눌러 펼친다. 지금 읽는 항목(읽는 위치 이전의 마지막 항목)은 색으로 표시하고, 그 항목까지 펼치고 그 근처로 스크롤해 둔다. 맨 위 항목이 하나뿐이면(책 제목) 펼쳐 둔다.
- 항목을 누르면 그 쪽의, 알 수 있으면 그 위치(상단 바 바로 아래)로 가고 서랍이 닫힌다.
- 형식별 목차:
  | 형식 | 목차 |
  |---|---|

**암호 PDF** (11장 29번)
- 암호가 걸린 PDF 탭은 페이지 대신 "암호가 걸린 문서입니다"와 암호 입력칸(가려진 글자), `탭 닫기` `열기`를 보여준다. 키보드의 완료 키 = 열기. 옆 탭이 미리 열리는 중에 키보드가 뜨지 않도록 입력칸에 저절로 들어가지 않는다.
- 틀리면 입력칸 아래에 "암호가 맞지 않습니다."
- 암호는 **앱이 켜져 있는 동안만 메모리에** 기억한다 (파일마다). 탭을 넘겼다 돌아와도, 탭 전환 화면의 썸네일도 다시 묻지 않는다. 앱을 완전히 끄면 다음에 다시 묻는다. 디스크·DB·백업 어디에도 쓰지 않고, 이 탭의 썸네일도 디스크 캐시에 남기지 않는다.
- 암호로 연 문서가 열려 있거나 탭 전환 화면에 그 썸네일이 있는 동안, Android가 최근 앱 목록용으로 저장하는 화면 미리보기에서 앱 화면을 뺀다. Android 13 이상은 미리보기만 빼고 스크린샷은 된다. 12 이하는 방법이 화면 보호(FLAG_SECURE)뿐이라 그동안 스크린샷도 막힌다. 그런 문서에서 복사한 글은 클립보드 미리보기에 뜨지 않게 민감 표시를 붙인다(Android 13+).
- 검색·선택·링크와 같은 Android의 PDF 기능으로 연다: Android 15+, 그리고 시스템 업데이트를 받은 Android 12–14. 그 밖의 기기는 "이 기기에서는 암호 PDF를 열 수 없습니다."
- 파일 묶음 안의 암호 PDF는 열 수 없는 파일처럼 빈 쪽 하나로 둔다.
- 권한 암호(인쇄·복사 제한)만 걸린 PDF는 묻지 않고 그대로 열린다.

### 5.6 설정 (최소화)
`⋮` → `설정`으로 여는 전체 화면 (Android 설정 앱 모양: 구역별 줄, 여럿 중 하나는 라디오 버튼, 켜고 끄기는 스위치). 뒤로 가기나 `←`로 닫는다.
항목 이름은 짧은 명사형, 설명은 "~합니다"로 끝나는 한 문장(Android 설정 앱의 어투). 뜻이 이름에 다 들어 있으면 설명을 달지 않는다.
- 화면: 테마 (시스템 기본값 / 밝은 테마 / 어두운 테마, 기본 시스템), 화면 켜짐 유지 ("문서를 보는 동안 화면이 꺼지지 않습니다.")
- 탭: 다음 그룹으로 넘기기 ("그룹의 마지막 탭에서 밀면 다음 그룹의 탭으로 넘어갑니다.", 기본 꺼짐 — 5.2), 여러 파일은 새 그룹으로 열기 (기본 켜짐 — 5.1)
- 필기: 펜 사용 (자동 / 항상 / 사용 안 함, 기본 자동 — 5.8.3. 항상 = 펜으로만 그림, 사용 안 함 = 손가락으로도 그림), 측면 버튼 (지우개 / 실행 취소 / 사용 안 함, 기본 지우개 — 5.8.4)
- 정보: 앱 정보 — 설정과 같은 전체 화면. 가운데에 앱 아이콘·이름·버전·한 줄 소개, 그 아래 줄로 `개인정보`(인터넷을 쓰지 않고 데이터를 보내지 않음)와 `오픈소스 라이선스`(라이브러리 목록 → 라이선스 전문). 저장소 링크는 두지 않는다

### 5.7 지원 형식 ★확장

**원칙: 모든 파일을 "고정 폭 페이지"로 그린다.**

```
파일 → 형식 판별 → 형식별 해석기 → 문서 { 페이지 수, 페이지 크기, 페이지 그리기 } → 뷰어
```

- 뷰어·썸네일·읽던 위치·페이지 이동·빠른 스크롤·탭 넘김 제스처·필기는 이 "문서" 하나만 상대한다 → 형식이 늘어도 뷰어는 그대로다.
- **원래 페이지가 있는 형식**(PDF, 이미지, pptx 슬라이드)은 그 크기 그대로 쓴다.
- **글이 흐르는 형식**(txt, md, docx, hwpx)은 화면 폭이 아니라 **정해진 가상 폭**으로 줄을 나누고 페이지 높이로 잘라, 화면에 맞게 확대·축소해서 보여준다.
  - txt·md: 휴대폰 화면 폭에서 읽기 좋은 글자 크기에 맞춘 고정 폭 (폭 1000단위에 본문 34단위). docx·hwpx: 문서에 적힌 용지 폭 (7단계).
  - 페이지는 줄 사이에서만 자른다 (줄 하나가 두 페이지에 걸치지 않음).
  - 이유: 필기는 "몇 페이지의 어느 위치"로 저장된다. 화면 폭에 맞춰 줄이 다시 나뉘면 화면 회전·기기 변경 때 글자가 움직여 필기가 어긋난다. 폭을 고정하면 위치가 항상 같다.
  - txt·md는 페이지 사이 간격 없이 이어 붙여 보여준다 (페이지 단위는 내부 구분일 뿐). docx·hwpx는 문서처럼 페이지 사이에 간격을 둔다.
- 정확도 목표: **원본과 크게 틀어지지 않는 수준.** 지원하지 않는 요소는 빈 상자와 "표시할 수 없는 개체"로 자리만 표시하고, 나머지는 계속 그린다.
- 글꼴: 문서의 글꼴을 내장하지 않고 시스템 글꼴(한글 포함)의 고딕/명조/고정폭 계열로 대응시킨다. 글꼴 폭이 원본과 조금 달라 줄이 바뀌는 단어 위치는 다를 수 있다.
  - **docx는 Word와 같은 자리에서 줄과 쪽이 끝나게 한다** (11장 39번): 그리기는 시스템 글꼴로 하되, 글자마다 원래 글꼴(Word가 쓰는 글꼴)의 폭이 되도록 자간을 맞추고, 줄 높이도 원래 글꼴로 정한다. 글꼴 치수는 Windows PC의 글꼴에서 뽑은 표(`office-fonts.bin`, 한국어 글꼴 전부와 흔한 영문 글꼴 약 110종, 숫자만)에 둔다. Word의 규칙(측정): 한 줄 = 한국어 글꼴은 글꼴 높이의 1.3배, 영문 글꼴은 글꼴 높이 그대로, 줄마다 그 줄의 가장 큰 글꼴 기준. 한글 옆 공백은 한글 글꼴의 반각 폭. 한글은 글자 크기를 1/600인치 단위로 반올림한 크기로. 영문은 Word처럼 커닝. 행 높이에 테두리 두께 포함. 쪽 끝 문단의 뒤 간격은 다음 쪽으로 넘기지 않는다
  - 표에 없는 글꼴은 고딕/명조 계열의 시스템 글꼴 폭 그대로(한국어 글꼴이면 맑은 고딕 치수). 이때 어긋남을 줄이려고 Word가 저장할 때 남긴 쪽 끝 위치(`lastRenderedPageBreak`)를 따른다: 이 앱의 쪽 끝과 가까우면(쪽 높이의 5% 안, 아래 여백으로 조금 넘치는 것 허용) Word의 위치에서 쪽을 나눈다

### 5.8 필기 ★확장

#### 5.8.1 저장 범위
- 필기는 **탭마다** 따로 저장한다. 같은 파일을 두 탭으로 열어도 각각의 필기를 가진다.
- **원본 파일에는 저장하지 않는다.** 필기는 앱 안에만 있다.
- 앱을 꺼도 열린 탭의 필기는 유지된다 (5.3).
- 탭을 닫으면 필기도 지운다. 단, 실행 취소 스낵바가 떠 있는 동안(약 10초)은 남겨 두고, 되돌리면 함께 복원한다.
- 위치는 "페이지 번호 + 페이지 안의 상대 좌표"로 저장 → 확대율·화면 크기·회전과 상관없이 같은 자리에 보인다 (5.7 고정 폭 원칙).

#### 5.8.2 도구
| 도구 | 동작 | 조정 |
|---|---|---|
| 펜 | 불투명 선. 펜 압력이 있으면 굵기에 반영 | 색(기본 8색 + 직접 고르기, 최근 직접 고른 색 1개), 굵기(슬라이더 + 숫자 + 실시간 미리보기), 프리셋 |
| 형광펜 | 반투명 선, 겹쳐도 진해지지 않음, 글자 위에 칠해도 글자가 보임 | 색(형광 계열 기본 5색 + 직접 고르기, 최근 직접 고른 색 4개), 굵기, 프리셋 |
| 지우개 | 닿은 **획 전체**를 지움 | 지우개 크기 (범위를 원으로 미리보기) |
| 되돌리기 / 다시 하기 | 그 탭의 필기 작업 단위 (그리기, 지우기) | — |

- 도구별 마지막 색·굵기는 앱 전체 설정으로 기억한다 (탭마다가 아님).
- **프리셋**: 펜·형광펜마다 색과 굵기 한 벌을 6개까지 저장한다. 도구 패널 맨 위 줄에 원(종이 흰색 위에 그 색의 점, 굵을수록 큰 점)으로 보이고, 누르면 그 색·굵기가 된다. `＋`는 지금 색·굵기를 끝에 더한다(같은 것이 있거나 6개면 흐림). 길게 누르면 삭제. 도구 막대에는 두지 않는다.
- 굵기 숫자는 페이지 폭을 1000으로 본 단위의 값이다(0.5 단위).
- 2차: 도형 보정, 페이지 단위 필기 지우기.

#### 5.8.3 입력 규칙 (굿노트 방식)

**필기 모드는 `✎` 버튼으로만 켠다.** 필기 모드가 꺼져 있으면 펜도 손가락과 똑같이 스크롤·탭 넘김·확대만 한다 → 뷰어로 쓸 때 실수로 그어지는 일이 없다.

| 필기 모드 | 기기 | 펜 | 한 손가락 | 두 손가락 |
|---|---|---|---|---|
| 끔 | 모든 기기 | 손가락과 같음 | 스크롤, 탭 넘김 (5.2) | 확대/축소 |
| 켬 | 펜을 쓰는 기기 | **그림** | 스크롤, 탭 넘김 (5.2 그대로) | 확대/축소 |
| 켬 | 펜이 없는 기기 | — | **그림** | 스크롤, 확대/축소 (탭 넘김은 하지 않음 — 11장 13번) |

- "펜을 쓰는 기기" 판단 (설정 `펜 사용`):
  - **자동(기본)**: 필기 모드에서 펜 입력을 한 번이라도 받으면 그때부터 손가락은 그리지 않는다. 이 판단은 기억한다.
    - 펜을 넣어 두고 손가락으로 그리고 싶을 때는 도구 막대의 `☝` 버튼을 켠다. 켜 두면 손가락도 그리고(스크롤은 두 손가락), 펜이 다시 화면에 닿거나 가까이 오면 저절로 꺼진다. 켠 상태는 기억한다 (11장 28번).
  - 항상: 펜으로만 그린다. 손가락은 절대 그리지 않는다.
  - 사용 안 함: 펜이 있어도 손가락도 그린다 (이때 스크롤은 두 손가락).
- 손바닥 무시: 펜이 화면에 닿아 있거나 가까이 있는 동안의 손가락·손바닥 입력은 무시한다. 시스템이 손바닥으로 판정해 취소한 입력(ACTION_CANCEL / FLAG_CANCELED)은 그리던 획을 지운다.
- 손가락으로 그리는 모드에서 두 손가락을 대면, 이미 그리기 시작한 첫 손가락의 획은 취소하고 스크롤·확대로 넘어간다.
- 한 획이 쪽 경계를 넘어가면 지나간 쪽마다 그 쪽에 그어진 부분으로 나눠 저장한다 (되돌리기는 한 번에). 지우개도 지나간 쪽들의 획을 지운다 (11장 37번).
- 필기 모드는 저장하지 않는다. 앱을 새로 열면 항상 꺼진 상태(보기 전용)로 시작한다.

#### 5.8.4 펜 측면 버튼 (갤럭시 S펜 등)
- 설정 "측면 버튼"으로 고른다 (아이비스페인트처럼 버튼에 기능 하나를 고르는 방식):
  - **지우개**(기본): 필기 모드에서 측면 버튼을 누른 채 그리면 지우개로 동작한다. 버튼을 떼면 원래 도구로 돌아온다 (갤럭시 기본 노트 앱과 같은 감각).
  - **실행 취소**: 펜을 화면에서 띄운 채 버튼을 누르면 한 번 되돌린다. 누른 채 화면에 대면 보통처럼 그린다.
  - **사용 안 함**
  - 버튼 판정: 획을 시작할 때 Android 표준 펜 버튼 상태(BUTTON_STYLUS_PRIMARY, 일부 기기는 BUTTON_SECONDARY)를 본다. 실기기(S펜)에서 의도대로 동작함을 확인했다 (2026-10-25).
- 지우개 끝이 달린 펜(TOOL_TYPE_ERASER)은 그 끝으로 지운다.
- 펜을 화면 가까이 띄우면(호버) 펜 굵기나 지우개 범위를 원으로 미리 보여준다.
- 필기 모드가 꺼져 있을 때 측면 버튼은 아무 동작도 하지 않는다.

#### 5.8.5 표시
- 확대해도 선이 깨지지 않게 벡터(획 좌표)로 저장하고 그때그때 그린다.
- 탭 전환 화면의 썸네일에도 필기를 함께 그린다.
- 펜 지연을 줄이기 위해 그리는 중인 획은 저지연 렌더링(전면 버퍼)으로 그린다.

### 5.9 PDF로 내보내기
탭 하나를 **필기와 함께 PDF 파일 하나로** 만든다. 형식은 상관없다 (11장 30번).

- `⋮` → `PDF로 내보내기` → `저장`(시스템의 "다른 이름으로 저장" 화면, 이름은 원래 파일 이름.pdf) 또는 `공유`(공유 시트). 탭이 열리지 않은 상태(파일 없음, 암호 입력 전)에서는 메뉴가 꺼져 있다.
- 만드는 동안 진행 막대(`12 / 240`)와 `취소`. 끝나면 저장은 "PDF로 저장했습니다", 공유는 공유 시트.
- 만드는 방식 — 형식마다 가장 많이 남는 방법:
  | 탭 | 방식 | 결과 |
  |---|---|---|
  | PDF | **원본 파일 뒤에 필기만 덧붙인다** (PDF 증분 업데이트) | 원본의 글자·벡터·링크·목차·양식이 그대로. 크기는 원본 + 필기. 페이지 회전·잘라낸 영역(CropBox)이 있어도 화면에서 본 자리에 |
  | 텍스트·마크다운·HTML·epub·docx·hwpx·hwp·pptx·xlsx | Android PDF 쓰기 기능으로 **글자를 글자로** 그린다 | 다른 앱에서 찾기·복사가 된다. 종이 폭: 문서의 용지(docx·hwp·pptx), 시트 폭(xlsx), 휴대폰 폭 문서(텍스트·HTML·epub)는 360pt |
  | 이미지·파일 묶음 | 쪽마다 JPEG 그림(200dpi, 품질 85) | Android PDF 쓰기 기능은 그림을 압축하지 않아(사진 한 쪽 약 5.5MB) 직접 쓴다 |
- 필기는 언제나 그림이 아닌 **선(벡터)**으로 넣는다. 형광펜은 반투명이라 글자가 비친다.
- PDF의 구조를 따라갈 수 없는 파일(깨진 파일 등)은 쪽을 JPEG 그림으로 넣는다. 결과는 Android로 다시 열어 쪽 수를 확인한 뒤에만 쓴다.
- 암호 PDF(5.5): 내보내기 전에 "내보낸 PDF에는 암호가 걸리지 않습니다"라고 알린다. Android가 암호를 푼 사본을 만들고 그 뒤에 덧붙인다.
- 열 때 암호는 없고 인쇄·복사 등만 제한한 PDF: 암호화를 그대로 두고 덧붙이는 필기도 같은 키로 암호화한다 → 제한이 그대로 남는다 (RC4·AES-128·AES-256).
- 공유용 파일은 앱 캐시의 `export/`에 마지막 하나만 둔다 (다음 내보내기 때 지움). 저장한 경우에는 남기지 않는다.

## 6. 데이터 모델

```
TabGroup
  id: String (UUID)
  name: String          // 비어 있으면 "탭 n개"로 표시
  color: Int            // 팔레트 인덱스
  position: Int         // 최상위 순서 (그룹 없는 탭과 같은 순서 공간)

Tab
  id: String (UUID)
  groupId: String?      // → TabGroup.id, 없으면 그룹 없는 탭
  position: Int         // 그룹 안 순서, 그룹 없는 탭이면 최상위 순서
  uri: String           // 영구 권한을 받은 URI 또는 내부 복사본 경로
  isInternalCopy: Bool  // true면 탭 닫을 때 파일 삭제
  displayName: String
  format: String        // 판별한 형식 (pdf, text, markdown, image, unsupported; 7·8단계에 docx, hwpx, pptx) — v3
  page: Int
  pageOffset: Float     // 페이지 내 세로 위치 (페이지 높이 대비 비율)
  zoom: Float
  panX: Float           // 좌우 이동 (화면 폭 대비 비율)
  lastOpenedAt: Long

InkStroke                // v4
  id: String (UUID)
  tabId: String         // → Tab.id (외래 키 없음 — 실행 취소 기간 동안 남겨 두려고)
  page: Int
  seq: Long             // 그린 순서
  tool: String          // pen, highlighter
  color: Int            // ARGB
  size: Float           // 페이지 폭 대비 비율
  points: Blob          // 획 좌표·압력 (필기 라이브러리의 직렬화 형식)

AppState
  currentTabId: String?
```

- 저장소: 로컬 DB(Android Room / SQLite). 수십~수백 개 탭 규모에서도 충분히 가볍다.
- 썸네일: 탭 전환 화면용 저해상도 이미지를 캐시 폴더에 저장 (지워져도 재생성 가능). 필기가 바뀌면 그 탭 썸네일을 다시 만든다.
- DB 버전 2부터 그룹 없는 탭 구조. 버전 1(모든 탭이 그룹에 속하던 구조)에서 올라오면 자동 생성됐던 "기본" 그룹의 탭은 그룹 없는 탭이 되고 나머지 그룹은 유지된다.
- DB 버전 3 (5단계): `Tab.format` 추가. 기존 탭은 모두 `pdf`로 채운다. `unsupported`로 저장된 탭은 열 때마다 다시 판별한다 (새 버전이 읽을 수 있게).
- DB 버전 4 (6단계): `InkStroke` 추가. 탭이 닫히면 획도 지우되, 실행 취소 기간이 끝난 뒤에 지운다 (5.8.1).
- 되돌리기/다시 하기 기록은 저장하지 않는다 (앱을 다시 열면 비어 있음).

## 7. 기술 방향 (확정)

**Android 네이티브**로 개발한다. 제스처·펜 입력 제어와 성능에 유리하다. iOS는 추후 검토한다.

| 항목 | 선택 |
|---|---|
| 언어/UI | Kotlin + Jetpack Compose (Material 3, 앱 자체 색·글자·모양 체계: 4.4) |
| UI 글꼴 | Pretendard Std (SIL OFL 1.1, 3굵기 약 0.95MB → APK 압축 후 약 +0.5MB). 앱 화면에만 쓰고 문서 조판에는 쓰지 않는다 |
| PDF 렌더링 | Android 기본 `PdfRenderer` |
| 텍스트 인코딩 판별 | `juniversalchardet` (Mozilla 판별기. Android 공개 API에는 ICU `CharsetDetector`가 없음) |
| 마크다운 | `commonmark-java` (+ 표·작업 목록 확장)로 해석, 그리기는 직접 |
| HTML | `jsoup`(HTML 해석, 약 0.5MB)로 DOM을 만들고, CSS 적용·변환(`HtmlReader`)은 직접 → 오피스 공통 모델 → `OfficeLayout.flow` |
| docx / pptx / hwpx / xlsx | 직접 해석 (zip + `XmlPullParser`) → 공통 중간 모델(`OfficeDocument`) → 용지 단위 조판(`OfficeLayout`, `SheetDocument`). 줄 높이·기준선 등은 Word·한글이 직접 만든 PDF와 나란히 비교해 맞춘 값. docx는 글꼴 치수 표(`OfficeFonts`, `tools/office-font-metrics.py`로 Windows 글꼴에서 생성, 약 200KB)로 Word의 글자 폭·줄 높이를 따른다 (5.7). 맞춤 정도는 Word로 만든 시험 문서(`tools/word-fit.ps1`)를 Word의 PDF와 비교하는 계측 테스트 `WordFitTest`로 확인한다. pptx는 슬라이드 모델(`Presentation`) → 슬라이드 단위 그리기(`SlideDocument`), 글상자 안 글은 같은 조판(`OfficeLayout.box`)을 쓴다. PowerPoint "한 줄" = 글자 크기의 1.2배 |
| 이미지 | `BitmapFactory`(필요한 해상도로 줄여 읽기) + `ExifInterface` |
| 글 조판 | `StaticLayout` 기반, 고정 가상 폭 |
| 필기 | Jetpack Ink (`androidx.ink`: 저지연 획 그리기, 브러시, 획 겹침 판정, 직렬화) |
| 탭 스와이프 | Compose `HorizontalPager` |
| 저장 | Room |
| 파일 접근 | SAF (`ACTION_OPEN_DOCUMENT`) + `takePersistableUriPermission()` |
| 최소 지원 버전 | Android 8.0 (API 26) 이상 (heic 등 일부 이미지는 기기 지원에 따름) |

- 널리 쓰이는 라이브러리는 쓴다. 다만 8장의 용량·시작 시간 목표는 지킨다.
- hwp는 `hwplib`(약 1MB, 의존성 없음)로 읽는다: HWP 5.0은 OLE 복합 파일 안의 압축된 이진 레코드라 직접 해석하는 비용이 크고, hwplib가 레코드를 객체로 풀어 주므로 그 위에서 hwpx와 같은 모델로 옮기기만 하면 된다 (11장 26번).
- 오피스 형식을 라이브러리로 하지 않는 이유: Apache POI는 Android에서 무겁고 화면에 그려 주지 않는다. 상용 SDK는 유료, LibreOffice 기반은 100MB가 넘는다. "크게 틀어지지 않는 수준"(5.7)에는 XML을 직접 읽는 쪽이 현실적이다. hwp 등을 추가할 때는 `hwplib` 같은 공개 라이브러리를 먼저 검토한다.
- PDF 텍스트 검색은 `PdfRenderer`의 글자 기능(Android 15의 `Page.searchText`, Android 12~14는 시스템 업데이트로 받는 `PdfRendererPreV`)을 쓴다. 목차·텍스트 선택에서 더 필요하거나 오래된 기기 지원이 중요해지면 PDFium 기반 라이브러리로 교체를 검토한다. (렌더러는 5.7의 "문서" 인터페이스 뒤에 있으므로 교체 비용이 작다.)

## 10. 리스크 및 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| 확대 상태에서 좌우 스와이프가 탭 전환과 헷갈림 | 높음 | 5.2의 "끝에 닿은 뒤 한 번 더" 규칙, 프로토타입 단계에서 실사용 테스트 |

| 필기 위치가 어긋남 (화면 회전, 파일 변경) | 높음 | 고정 폭 조판(5.7), 페이지 상대 좌표 저장. 파일 내용 자체가 바뀐 경우는 받아들인다 |
| 손가락 필기 모드에서 그리기와 스크롤 혼동 | 중간 | 두 손가락이 닿으면 첫 획 취소(5.8.3), 필기 모드는 버튼으로만 켬 |
| 펜 지연이 커서 필기감이 나쁨 | 중간 | 저지연 렌더링을 지원하는 Jetpack Ink 사용, 실기기 확인 |
| 탭이 매우 많을 때 메모리 부족 | 중간 | 인접 탭만 렌더링, 썸네일은 디스크 캐시 |
| 기본 `PdfRenderer`의 일부 PDF 호환성 문제 | 중간 | 렌더러를 인터페이스로 분리, 필요 시 PDFium으로 교체 |
| 악성·손상 문서 (압축 폭탄, 잘못된 XML) | 중간 | 압축 해제 크기 한도(기기의 앱 메모리 한도에 맞춰: 항목당 ¼, 합계 ½, 최대 64MB·200MB), XML 중첩 256단계까지, 외부 엔티티 해석 안 함. 메모리·스택이 부족해도 앱이 죽지 않고 "열 수 없음" 표시 — 죽으면 다음 실행 때 같은 탭을 다시 열어 계속 죽기 때문 (SecurityTest). 화면에 그릴 때 나는 예외는 잡을 수 없으므로 미리 막는다: 쪽 크기(0·무한·세로가 폭의 100배 초과)와 용지·여백을 열 때 검사, 쪽 높이에 맞춘 최대 배율, 화면에 그리는 그림은 90MB 이하(Android는 100MB 넘는 그림을 그리지 않고 앱을 끝냄), 썸네일은 100만 화소 이하. 조판이 끝나지 않는 파일: CSS 선택자 매칭은 실패를 기억하고 쪽마다 작업량 한도, PDF 교차 참조 스트림은 데이터 크기만큼만 읽음. hwp는 앱 메모리의 ¼(최대 128MB)까지. XML은 DTD를 처리하지 않음(파일 안에서 정의한 엔티티를 확장하지 않음, billion laughs). 표 행·열(1만·10만), PPTX 슬라이드(중복 제거·5000장), CSS 중첩·길이에 상한, 문서의 NaN·무한대 값은 받지 않음. 마크다운 그림은 합계 64MB까지만 풀고 나머지는 이름으로. 텍스트·EPUB 백그라운드 조판은 어떤 오류든 거기까지만 보여줌<br>**그림 형식 허용 목록**: Android는 이름·MIME이 아니라 내용으로 디코더를 고르고 앱이 보여주는 것보다 훨씬 많은 형식(DNG 같은 카메라 원본, 제조사 코덱 — 2025년 LANDFALL 공격 경로)을 연다. 문서 속 그림과 이미지 파일 모두 5.7의 형식(PNG·JPEG·GIF·BMP·WebP·HEIF)인지 첫 바이트로 확인한 뒤에만 디코딩. 다른 앱의 이미지는 열 때 한 번 복사해 그 사본만 읽음(프로바이더가 읽을 때마다 다른 내용을 줄 수 있음)<br>**잡을 수 없는 종료**(시스템 코드의 네이티브 충돌, 메모리 부족으로 인한 종료, 끝나지 않는 해석): 파일을 여는 동안 표시해 두고(no_backup/opening), 첫 쪽을 그린 뒤 지운다. 다음 실행 때 표시가 남은 탭은 저절로 열지 않고 "이 파일을 열다가 앱이 종료되었습니다"와 `다시 열기`<br>PDF는 Android의 PDF 기능(PDFium)을 쓰는 모든 일(쪽 그리기·검색·선택·링크·내보낼 때 암호 풀기·내보낸 파일 확인)을 권한 없는 격리 프로세스(isolatedProcess, Android 8.1+)에서 한다 — PDFium이 뚫려도 탭·필기·파일 권한에 닿지 않고, 충돌·메모리 고갈은 그 프로세스만 끝나며, 30초 넘게 걸리면 프로세스째 끝낸다. 돌려받은 크기·개수·좌표는 앱에서 다시 확인한다. 이미지 파일과 문서 안 그림의 디코딩도 같은 프로세스에서 한다(픽셀은 앱이 만든 메모리에, 앱이 예상한 크기까지만). HEIF만 앱에서 요청한다 — Android가 시스템 미디어 서비스(따로 격리된 시스템 프로세스)에서 해석하는데, 격리 프로세스는 그 서비스에 닿을 수 없다. HEIF 상자에 AVIF 표시가 있으면(다른 디코더로 감) 열지 않는다 |
| 이 앱 자신의 파일을 가리키는 주소 | 중간 | 다른 앱이 이 앱의 FileProvider 주소(내보내기 폴더)를 보내면 받지 않는다. 암호 PDF를 내보내는 동안의 작업 파일은 공유 폴더 밖에 둔다. 저장된 세션의 주소로 지우거나 쓰는 것은 앱이 만든 사본·묶음 폴더 안만 |
| 문서 속 링크 | 중간 | http·https·mailto만 연다 (file:·content:·intent: 등은 앱이 죽거나 다른 앱에 조작된 주소를 넘김). 읽을 때와 열 때 두 번 확인 |
| 다른 앱이 넘긴 파일 주소 | 중간 | content:// 만 받는다. file:// 는 이 앱의 내부 파일(DB, 다른 탭의 복사본)을 가리킬 수 있다 |
| 텍스트 인코딩 오판 (한글 깨짐) | 낮음 | BOM → UTF-8 엄격 검사 → 판별기 순, 2차로 인코딩 직접 선택 메뉴 검토 |
