# 앱 화면 한국어 문구 규칙

앱 화면의 글은 짧고, 같은 말을 여러 화면에서 반복한다. 그래서 한 대상을 한 용어로 부르는 것과 Android·오피스 앱에서 익숙한 전문 용어를 쓰는 것이 가장 중요하다. 2026-11 화면 다듬기(기획서 결정 40)에서 만들었다.

참고한 자료:
- [dotoricode/korean-humanizer](https://github.com/dotoricode/korean-humanizer) (MIT, Copyright (c) 2026 dotoricode): 한국어 AI 글투 패턴. 번역투, "해당/이러한", 이중 피동, 습관적 쉼표·줄표 항목을 가져왔다.
- [sickn33/agentic-awesome-skills의 ux-copy](https://github.com/sickn33/agentic-awesome-skills/tree/main/skills/ux-copy) (MIT, 원출처 bitjaru/styleseed): 버튼은 동작 이름, 오류는 무슨 일과 할 일, 한 개념에 한 용어.
- 다른 점: korean-humanizer는 "활용 → 쓰기"처럼 쉬운 말로 바꾸라고 하지만, 이 앱의 화면 문구는 **전문 용어로 통일**한다(사용자 결정). 구어체("밀면", "넘기기", "엶")를 표준 용어("스와이프", "이동", "참조")로 바꾸는 쪽이다.

## 1. 용어 목록

같은 대상은 아래 용어 하나로만 부른다. 새 기능에 용어가 필요하면 이 표에 먼저 더한다. 기획서와 README도 같은 용어를 쓴다.

| 대상 | 쓰는 용어 | 쓰지 않는 말 |
|---|---|---|
| 문서의 한 면 | 페이지 (`12페이지`) | 쪽, p., 면 |
| 문서 안 글자 찾기 | 검색, 검색어, 검색 닫기 | 찾기, 찾을 내용 |
| 사라진 파일을 다시 고르기 | 파일 다시 선택 | 다시 찾기 |
| 목록·그룹·묶음에서 없애기 | 제거 (`그룹에서 제거`) | 빼기 |
| 파일·데이터 지우기 | 삭제 | 지우기 (지우개 도구 이름은 예외) |
| 직전 동작 되돌림 | 실행 취소, 다시 실행 | 되돌리기, 다시 하기 |
| 색 | 색상 (`그룹 색상`, `사용자 지정 색상`) | 색 (단독) |
| 색상환·색상 막대의 각도 | 색조 | 색상 |
| 새로 만들기 확인 버튼 | 생성 | 만들기 |
| 이름 바꾸기 | 이름 변경 / 확인 버튼 `변경` | 이름 바꾸기 |
| 좌우로 미는 동작 | 스와이프 | 밀기, 넘기기 |
| 여러 파일을 한 탭으로 | 파일 묶음, `파일 묶음으로 열기` | 하나로 묶어 열기 |
| 파일마다 탭 하나씩 | 개별 탭 (`개별 탭으로 열기`) | 따로 열기 |
| 손가락으로 필기하는 모드 | 손가락 필기 | 손가락으로 그리기 |
| 마지막으로 보던 곳 | 마지막 위치 | 읽던 위치 |
| 원본 파일을 복사하지 않고 열기 | 원본 파일 직접 참조 | 원본 파일을 직접 엶 |
| 암호 PDF | 암호로 보호된 문서 | 암호가 걸린 문서 |
| DRM 문서 | DRM이 적용된 문서 | 보호된 문서 |

그대로 쓰는 표준 용어: 열기, 닫기, 공유, 저장, 취소, 이동, 설정, 목차, 앱 정보, 오픈소스 라이선스, 테마, 시스템 기본값, 펜, 형광펜, 지우개, 프리셋, 굵기, 채도와 밝기, 클립보드.

## 2. 문구 형식

- **버튼·메뉴**: 동작을 나타내는 명사형 2~4어절. `PDF로 내보내기`, `그룹에서 제거`, `파일 다시 선택`. "확인", "예"처럼 무엇을 하는지 모르는 말은 쓰지 않는다. 마침표 없음.
- **아이콘 버튼의 화면 낭독기 설명(contentDescription)**: 버튼 이름과 같은 형식. 화면에 글자로 쓰지 않는다(CLAUDE.md 구현 원칙).
- **제목**: 상황을 이름으로. `파일 4개 열기`, `암호로 보호된 문서입니다`. 느낌표 없음.
- **오류 안내**: 제목은 무슨 일인지, 설명은 원인이나 할 일을 한 문장으로. `파일을 찾을 수 없습니다` + `파일이 이동 또는 삭제되었을 수 있습니다.` + 버튼 `파일 다시 선택`. 기술 오류 코드나 예외 이름은 보여 주지 않는다.
- **대화상자**: 제목은 동작, 본문은 결과, 확인 버튼은 동작 이름, 닫기만 하는 버튼은 `닫기`, 하려던 동작을 그만두는 버튼은 `취소`.
- **토스트·스낵바**: 일어난 일을 "~했습니다"로. `클립보드에 복사했습니다`, `탭을 닫았습니다`. 되돌릴 수 있으면 `실행 취소` 동작을 단다.
- **설정**: 항목 이름은 짧은 명사형(`그룹 간 연속 이동`), 설명은 "~합니다."로 끝나는 한 문장(기획서 5.6). 이름으로 뜻이 다 전해지면 설명을 달지 않는다.
- **마침표**: 문장으로 된 설명에만 찍는다. 버튼·제목·라벨·메뉴에는 찍지 않는다.
- **어미**: 화면 전체를 "합니다"체로 맞춘다. 해요체·반말을 섞지 않는다.
- **숫자**: `탭 3개`, `12페이지`, `파일 4개`처럼 숫자 + 단위. 바뀌는 숫자는 고정폭 숫자(`tabularNumbers()`)로 그린다.

## 3. 걸러낼 AI 글투

korean-humanizer의 패턴 중 화면 문구에 자주 나오는 것.

- 번역투: "~를 통해", "~에 의해", "~에 있어서", "~에 대한"이 많음 → 조사와 서술어로 푼다.
- "해당", "이러한", "~하는 것입니다" → 대상을 바로 쓰거나 지운다.
- 이중 피동 "~되어집니다", 주체를 숨긴 "~될 수 있습니다"의 남발 → "~됩니다", "~할 수 있습니다".
- 줄표(—)와 연결어미 뒤 습관적 쉼표 → 쉼표·괄호나 두 문장으로.
- 과장·감탄: "손쉽게", "강력한", "완벽하게", 느낌표, 이모지 → 지운다.
- 근거 없는 단정·약속: "절대", "항상 안전" → 사실만. 확인한 사실은 그대로 쓴다(예: 매니페스트에 권한이 없으므로 "인터넷 권한을 사용하지 않으며").
- 같은 내용을 두 번 말하는 제목·설명 → 설명을 지우거나 원인·할 일로 바꾼다.

사실·숫자·파일 형식 이름·버전은 문체를 고치느라 바꾸지 않는다. 바꾸기 전에 코드에서 실제 동작을 확인한다(예: 그룹 간 연속 이동은 첫 탭에서도 앞 그룹으로 이동한다).

## 4. 바꾼 뒤 확인

1. 바꾼 문자열을 계측 테스트가 찾는지 확인한다: `app/src/androidTest`에서 옛 문구를 Grep (예: `InkInputTest`는 손가락 필기 버튼을 설명으로 찾는다).
2. 코드 주석과 기획서·README에 옛 문구가 남았는지 Grep.
3. 새 용어를 쓰지 않는 말이 남았는지 Grep: `"[^"]*(쪽|빼기|되돌리기|다시 하기|찾기|따로 열기)[^"]*"` (지우개·검색 결과처럼 예외가 맞는지 본다).
4. `.\gradlew.bat assembleDebug`, 문구를 찾는 계측 테스트를 다시 돌린다.
5. 에뮬레이터에서 바뀐 화면을 캡처해 잘리거나 두 줄로 넘어간 곳이 없는지 본다.
